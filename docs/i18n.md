# Languages

Tokenping is published in English (the default, at the root) and in every language of the table below, each under
its prefix. The Czech URL prefix is `cz`, but the language code everywhere else
(`<html lang>`, hreflang, `Locale`, the `content/blog/cs` folder, `/og/cs`) stays `cs`, the ISO 639-1 code for Czech:
`cz` is the country code, and search engines ignore it as a language. Every other language uses its ISO code
everywhere. Spanish is one neutral Spanish for Spain and Latin America. Hindi is Devanagari, with Latin digits and the
Western digit grouping the app shows ("12,000", never the lakh grouping "12,00,000"). German is one German for
Germany, Austria and Switzerland (hreflang `de`). Vietnamese is hreflang `vi`. Dutch is one Dutch for the Netherlands and Flanders (hreflang `nl`), Romanian one Romanian for Romania and Moldova (hreflang `ro`). Hungarian is hreflang `hu`. This page explains how the languages
are wired and how to write each one in the English voice. Read `docs/design-system.md` too: its voice rules apply in
every language.

## URLs

and `blog/<slug>`, plus a privacy page whose path has the language's word.

English and German also name the countries that read them (`regions` in `LOCALE_INFO`): the UK and the US, and
Germany, Austria and Switzerland. Each gets its own hreflang (`en-GB`, `de-AT` and so on) pointing at the same page and
its own entry in the language menu, which lists every entry by its short label; there is still one set of pages and
URLs per language.

Slugs are lower-case ASCII in every language: Czech, German and Vietnamese words lose their diacritics ("ä" is "ae",
"ö" "oe", "ü" "ue", "ß" "ss"; Vietnamese "đ" is "d"), and Hindi slugs are Latin transliterations, as Indian sites
write Hindi URLs.

Each language's prefix and privacy word are written once, in `packages/nextjs/i18n/localePaths.ts` (alias-free,
because `next.config.ts` imports it for the Link headers and markdown rewrites); `i18n/routes.ts` builds every page
path from it. Never hard-code `"/aave"` or `"/blog/..."` in a component: use `routePath(locale, "dashboard")` and
`postPath(locale, slug)`. Post slugs pair up in `i18n/postSlugs.ts`, keyed by the English slug; the order of its
entries is the posts' order (hub first) in every language. `content/blog/posts.ts`, which imports every post file, is
generated from it by `yarn next:blog-index`, and a test fails when it is stale. The developer pages (`/admin`,
`/debug`, `/blockexplorer`) are English only.

## How it is wired

- `app/(en)/layout.tsx`, `app/(cs)/layout.tsx` and the other languages' layouts are one root layout per language
  (`components/RootDocument.tsx`), so `<html lang>` is correct on the server without middleware. Switching language
  is a full page load.
- Route files are thin: they render a shared page component from `components/pages/` with a `locale`. Every
  language's route group except English's, and every `i18n/client/<locale>.tsx`, is generated from
  `scripts/localeRoutes.ts` (`yarn next:locale-routes`); a test fails when a file differs from its template. A language
  that needs a web font adds it to `LAYOUT_FONTS` there.
- **Server components** receive `locale` as a prop and read strings directly: `HOME_MESSAGES[locale]`.
- **Client components** read their strings from context: `const t = useMessages("dashboard")` or `useLocale()`
  (`i18n/LocaleProvider.tsx`). Each root layout mounts its language's client root, `i18n/client/<locale>.tsx`, which
  imports that language's files of the client areas (alerts, blog, calculator, common, dashboard, morpho) and renders
  `components/ClientRoot.tsx` (theme, language, wallet providers, analytics). So a page's JavaScript carries one
  language: `next.config.ts` gives each language's message files their own chunk, and
  `i18n/client/clientMessages.test.ts` fails if code that runs in the browser imports a message index. Tests render
  without a layout: Vitest points `i18n/client/fallback.ts` at `fallback.vitest.ts`, which serves every language
  (English without a `<LocaleProvider locale>`).
- Strings live in `i18n/messages/<area>/`, one folder per area: `shared.ts` holds the area's types and helpers,
  `<locale>.ts` one language (`export const MESSAGES: DashboardMessages`), and `index.ts` assembles every language for
  server code (`DASHBOARD_MESSAGES[locale]`). A missing key is a type error in that language's file:

```ts
// i18n/messages/dashboard/shared.ts
export type DashboardMessages = {
  refresh: string;
  assets: (count: number) => string;
};

// i18n/messages/dashboard/cs.ts
export const MESSAGES: DashboardMessages = {
  refresh: "Obnovit pozice",
  assets: (n) =>
    plural("cs", n, {
      one: `${n} aktivum`,
      few: `${n} aktiva`,
      other: `${n} aktiv`,
    }),
};

// i18n/messages/dashboard/index.ts
export const DASHBOARD_MESSAGES: Localized<DashboardMessages> = {
  en,
  cs,
  es,
  hi,
  de,
  vi,
};
```

A missing string in any language is a type error. Interpolate with functions, never with string concatenation in
the component, because word order differs.

- `i18n/format.ts`: `plural` (by CLDR, with every category a language may use: zero, one, two, few, many, other;
  Czech one / few / many / other, English, Spanish and German one / other, Hindi one / other with 0 as one, Vietnamese
  other only), `formatLongDate` ("14. října 2026", "14 de octubre de 2026",
  "14 अक्टूबर 2026", "14. Oktober 2026", "14 tháng 10, 2026"), `joinList` ("Signal, Telegram a e-mail", "Signal,
  Telegram y correo electrónico", "Signal, Telegram और ईमेल", "Signal, Telegram und E-Mail", "Signal, Telegram và
  email", no comma before the last word; Spanish "y" becomes "e" before an i sound and "o" becomes "u" before an o
  sound; a language can set its own separator, such as Chinese "、", and join the last word without spaces) and
  `formatDecimal` (the decimal mark of the language's number format, read from Intl: a comma in Czech, German and
  Vietnamese; Spanish and Hindi keep the decimal point). `LOCALE_INFO[locale].numbers` is the Intl tag for numbers: the language's own, except Hindi,
  which uses `en-US` so amounts group in thousands like the app. Market wording: `csOnMarket`, `esMarket`, `hiMarket`,
  `deOnMarket`, `viMarket`.
- The tests hold every language to its voice through one file per language in `utils/testing/languageRules/`: the
  article disclaimer, the Sources heading, how a source's fetched date reads, the words for "free" (which
  `FREE_WORDS` in `utils/testing/copyRules.ts` joins for the page tests), the phrases the language must not use (on top
  of the English list in `content/blog/content.test.ts`) and, for a language written without spaces, how its words
  are counted for `readingMinutes` (`Intl.Segmenter`).
- Metadata: pass `locale` and `alternates` (`routeAlternates(...)`, or only the published translations of a post) to
  `pageMetadata`. It writes the canonical, hreflang with `x-default` English, `og:locale` and the language's RSS link.
- Each alert channel has its own language, picked next to its recipient in the alert form; a new channel starts in
  the page's language (`notification_configs.email_locale`, `signal_locale`, `telegram_locale`). A channel
  without one is sent in `notification_configs.locale`, the page language the alert was last saved from. The alert
  text, the email subject and html and the test messages come from `i18n/messages/notifications/`; the cron and
  `POST /api/notifications/test` pick the language per channel.
- The Telegram bot's replies (`i18n/messages/telegram/`) follow the sender's Telegram app, not the site: Czech for
  Czech and Slovak (`cs`, `sk`), Spanish for any Spanish (`es`, `es-MX`, ...), Hindi, German and Vietnamese for those
  (`hi`, `de`, `de-AT`, `vi`), English otherwise.
- Fonts: Satoshi covers English, Czech, Spanish and German. It has no Devanagari, so the Hindi social cards add Noto
  Sans Devanagari (`app/fonts/og`, SIL Open Font License) as a fallback font and the Hindi pages fall back to the
  system's Devanagari font. It also lacks most Vietnamese letters (ơ, ư and the stacked tone marks), and a per-letter
  fallback would mix two typefaces inside one word, so the Vietnamese pages and cards use Plus Jakarta Sans (SIL Open
  Font License) for all text instead: `components/fonts/vietnamese.ts`, loaded only by `app/(vi)/layout.tsx`, and
  its OG files in `app/fonts/og`.
- The sign-in message the wallet signs carries a one-line statement in the page's language
  (`signInStatement` in `i18n/messages/alerts/`).

## Adding a language

Every step below is checked by a test or the type checker, so a missing piece fails `yarn next:check-types` or
`yarn next:test` rather than reaching production.

1. **Voice and glossary first**: a "<Language> voice" and "<Language> glossary" section in this file (form of address,
   number and date forms, the terms below, the words for "free" and the claims to avoid), so every translator of the
   language uses the same words.
2. **Wiring** in `packages/nextjs`:
   - `i18n/locales.ts`: the code in `LOCALES` and its `LOCALE_INFO` (htmlLang, ogLocale, intl and numbers tags, native
     and English name, menu label, regions if any);
   - `i18n/localePaths.ts`: the URL prefix (the ISO 639-1 code, `/cz` being the one exception) and the privacy word in
     ASCII;
   - `i18n/postSlugs.ts`: an ASCII slug for every post (transliterated for Cyrillic and Greek; the English slug for
     Thai, Chinese, Japanese and Korean);
   - `i18n/format.ts`: its list words, and a market helper only if its grammar needs one;
   - `utils/testing/languageRules/<locale>.ts`: disclaimer, Sources heading, fetched-date pattern, words for "free",
     banned phrases, and `reading.segmentWords` for a language written without spaces;
   - `app/api/telegram/bot.ts`: the Telegram `language_code` values that map to it;
   - a row in `app/localeHomePages.test.tsx`, and `CHANNEL_NAMES` / `EMAIL_BADGE` if its word for email differs;
   - a web font in `LAYOUT_FONTS` (`scripts/localeRoutes.ts`) and the OG card fonts if Satoshi lacks its script.
3. **Messages**: one file per area, `i18n/messages/<area>/<locale>.ts`, typed by the area's `shared.ts`.
4. **Routes**: `yarn next:locale-routes` writes the route group and the client root.
5. **Guides**: every post in `content/blog/<locale>/`, then `yarn next:blog-index`.
6. **Checks**: `yarn next:test`, `yarn next:check-types`, `yarn lint`, `yarn next:build`, then every page of the
   language served and checked (status, hreflang, OG card, sitemap, llms.txt). One commit per language.

The database already allows every planned language code (`20261102000000_allow_all_planned_alert_locales`).

## Czech voice

- Formal address, lowercase: **vy, váš, vám**, never tykání. Buttons and menu items use the infinitive
  ("Uložit upozornění", "Obnovit pozice", "Připojit peněženku"); sentences use the vy imperative ("Připojte
  peněženku, se kterou si půjčujete").
- Sentence case, as in English. No em or en dashes anywhere (ranges with a plain hyphen: "1,5-2,0").
- Czech quotation marks in running text: „takto". Decimal comma in prose ("1,66"); data shown in the dashboard
  (amounts, health factor badges) keeps the app's number format.
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date
  and caveat of the English. Never add claims.
- Dates in prose: "14. října 2026". "As of October 2026" is "k říjnu 2026".

## Spanish voice

- One neutral Spanish for Spain and Latin America. No voseo and no vosotros; avoid words only one region uses
  ("ordenador", "móvil", "celular", "coger"). Prefer the word both understand: "billetera" for wallet, "tasa" for
  rate, "costo" for cost, "teléfono" for phone.
- Informal address, **tú, tu, te**, never usted. Buttons and menu items use the infinitive ("Guardar alerta",
  "Actualizar posiciones", "Conectar billetera"); sentences use the tú imperative ("Conecta la billetera con la que
  pides prestado").
- Sentence case, as in English. Opening marks always: "¿Qué es el factor de salud?", "¡Listo!". No em or en dashes
  anywhere, no raya for asides (ranges with a plain hyphen: "1.5-2.0").
- Numbers as the app shows them and as Latin America writes them: decimal point ("1.66"), comma for thousands
  ("12,000 USDC", "$2,400"), percentages without a space ("83%").
- Dates in prose: "14 de octubre de 2026", months in lower case. "As of October 2026" is "a octubre de 2026".
- Double quotation marks: "así".
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date and
  caveat of the English. Never add claims.

## Hindi voice

- Standard Hindi (मानक हिंदी) in Devanagari, the register of a careful explainer, not of a bank's terms: short
  sentences, everyday words, the technical term in Latin script where Indian crypto readers use it that way.
- Polite address, **आप, आपका, आपको**, never तुम or तू. Buttons and menu items are short imperatives in the आप form
  ("अलर्ट सहेजें", "पोज़िशन रीफ़्रेश करें", "वॉलेट कनेक्ट करें"); sentences use the same form ("उस वॉलेट को कनेक्ट
  करें जिससे आप उधार लेते हैं").
- Sentences end with the danda "।", questions with "?". No em or en dashes anywhere; a colon, a comma or "से" for
  ranges ("1.5 से 2.0" or "1.5-2.0" with a plain hyphen). Straight double quotation marks "…".
- Numbers exactly as the app shows them: Latin digits, decimal point ("1.66"), Western thousands grouping
