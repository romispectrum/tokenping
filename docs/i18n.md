# Languages: English and Czech

Tokenping is published in English (the default, at the root) and Czech (under `/cz`). The URL prefix is `cz`, but the
language code everywhere else (`<html lang>`, hreflang, `Locale`, the `content/blog/cs` folder, `/og/cs`) stays `cs`, the ISO
639-1 code for Czech: `cz` is the country code, and search engines ignore it as a language. This page explains how the
two languages are wired and how to write Czech that matches the English voice. Read `docs/design-system.md` too: its
voice rules apply in both languages.

## URLs

| Page | English | Czech |
|---|---|---|
| Home | `/` | `/cz` |
| Dashboard | `/aave` | `/cz/aave` |
| Blog | `/blog` | `/cz/blog` |
| Post | `/blog/<slug>` | `/cz/blog/<czech-slug>` |
| RSS | `/blog/feed.xml` | `/cz/blog/feed.xml` |
| Privacy | `/privacy` | `/cz/ochrana-soukromi` |

`packages/nextjs/i18n/routes.ts` is the only place these paths are written. Never hard-code `"/aave"` or
`"/blog/..."` in a component: use `routePath(locale, "dashboard")` and `postPath(locale, slug)`. Post slugs pair up
in `i18n/postSlugs.ts`, keyed by the English slug. The developer pages (`/admin`, `/debug`, `/blockexplorer`) are
English only.

## How it is wired

- `app/(en)/layout.tsx` and `app/(cs)/layout.tsx` are two root layouts (`components/RootDocument.tsx`), so
  `<html lang>` is correct on the server without middleware. Switching language is a full page load.
- Route files are thin: they render a shared page component from `components/pages/` with a `locale`.
- **Server components** receive `locale` as a prop and read strings directly: `HOME_MESSAGES[locale]`.
- **Client components** read the language from context: `const t = useMessages(DASHBOARD_MESSAGES)` or
  `useLocale()` (`i18n/LocaleProvider.tsx`). Without a provider (unit tests) they are English.
- Strings live in `i18n/messages/<area>.ts`, one file per area, both languages in one typed object:

```ts
type DashboardMessages = { refresh: string; assets: (count: number) => string };

export const DASHBOARD_MESSAGES: Localized<DashboardMessages> = {
  en: { refresh: "Refresh positions", assets: n => plural("en", n, { one: `${n} asset`, other: `${n} assets` }) },
  cs: { refresh: "Obnovit pozice", assets: n => plural("cs", n, { one: `${n} aktivum`, few: `${n} aktiva`, other: `${n} aktiv` }) },
};
```

  A missing Czech string is a type error. Interpolate with functions, never with string concatenation in the
  component, because Czech word order differs.
- `i18n/format.ts`: `plural` (Czech has one / few / many / other), `formatLongDate` ("14. října 2026"),
  `joinList` ("Signal, Telegram a e-mail", no comma before the last word) and `formatDecimal` (Czech decimal comma
  in running text).
- Metadata: pass `locale` and `alternates` (`routeAlternates(...)`, or only the published translations of a post) to
  `pageMetadata`. It writes the canonical, hreflang with `x-default` English, `og:locale` and the language's RSS link.
- Each alert channel has its own language, picked next to its recipient in the alert form; a new channel starts in
  the page's language (`notification_configs.email_locale`, `signal_locale`, `telegram_locale`). A channel
  without one is sent in `notification_configs.locale`, the page language the alert was last saved from.

## Czech voice

- Formal address, lowercase: **vy, váš, vám**, never tykání. Buttons and menu items use the infinitive
  ("Uložit upozornění", "Obnovit pozice", "Připojit peněženku"); sentences use the vy imperative ("Připojte
  peněženku, se kterou si půjčujete").
- Sentence case, as in English. No em or en dashes anywhere (ranges with a plain hyphen: "1,5-2,0").
- Czech quotation marks in running text: „takto". Decimal comma in prose ("1,66"); data shown in the dashboard
  (amounts, health factor badges) keeps the app's number format.
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date
  and caveat of the English. Never add claims.
- Dates in prose: "14. října 2026". "As of October 2026" is "k říjnu 2026".
