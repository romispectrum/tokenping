# Languages: English, Czech, Spanish, Hindi, German and Vietnamese

Tokenping is published in six languages: English (the default, at the root), Czech (`/cz`), Spanish (`/es`), Hindi
(`/hi`), German (`/de`) and Vietnamese (`/vi`). The Czech URL prefix is `cz`, but the language code everywhere else
(`<html lang>`, hreflang, `Locale`, the `content/blog/cs` folder, `/og/cs`) stays `cs`, the ISO 639-1 code for Czech:
`cz` is the country code, and search engines ignore it as a language. Every other language uses its ISO code
everywhere. Spanish is one neutral Spanish for Spain and Latin America. Hindi is Devanagari, with Latin digits and the
Western digit grouping the app shows ("12,000", never the lakh grouping "12,00,000"). German is one German for
Germany, Austria and Switzerland (hreflang `de`). Vietnamese is hreflang `vi`. This page explains how the languages
are wired and how to write each one in the English voice. Read `docs/design-system.md` too: its voice rules apply in
every language.

## URLs

Every language has the same six pages under its prefix: home, `aave` (dashboard), `morpho`, `blog`, `blog/feed.xml`
and `blog/<slug>`, plus a privacy page whose path has the language's word.

| Language   | Code | Home  | Privacy                | Post slug example                        |
| ---------- | ---- | ----- | ---------------------- | ---------------------------------------- |
| English    | `en` | `/`   | `/privacy`             | `/blog/aave-health-factor`               |
| Czech      | `cs` | `/cz` | `/cz/ochrana-soukromi` | `/cz/blog/aave-health-factor-vysvetleni` |
| Spanish    | `es` | `/es` | `/es/privacidad`       | `/es/blog/factor-de-salud-aave`          |
| Hindi      | `hi` | `/hi` | `/hi/gopaniyata`       | `/hi/blog/aave-health-factor-kya-hai`    |
| German     | `de` | `/de` | `/de/datenschutz`      | `/de/blog/aave-health-factor-erklaert`   |
| Vietnamese | `vi` | `/vi` | `/vi/quyen-rieng-tu`   | `/vi/blog/he-so-suc-khoe-aave`           |

Slugs are lower-case ASCII in every language: Czech, German and Vietnamese words lose their diacritics ("ä" is "ae",
"ö" "oe", "ü" "ue", "ß" "ss"; Vietnamese "đ" is "d"), and Hindi slugs are Latin transliterations, as Indian sites
write Hindi URLs.

`packages/nextjs/i18n/routes.ts` is the only place these paths are written. Never hard-code `"/aave"` or
`"/blog/..."` in a component: use `routePath(locale, "dashboard")` and `postPath(locale, slug)`. Post slugs pair up
in `i18n/postSlugs.ts`, keyed by the English slug. The developer pages (`/admin`, `/debug`, `/blockexplorer`) are
English only.

## How it is wired

- `app/(en)/layout.tsx`, `app/(cs)/layout.tsx` and the other languages' layouts are one root layout per language
  (`components/RootDocument.tsx`), so `<html lang>` is correct on the server without middleware. Switching language
  is a full page load.
- Route files are thin: they render a shared page component from `components/pages/` with a `locale`.
- **Server components** receive `locale` as a prop and read strings directly: `HOME_MESSAGES[locale]`.
- **Client components** read the language from context: `const t = useMessages(DASHBOARD_MESSAGES)` or
  `useLocale()` (`i18n/LocaleProvider.tsx`). Without a provider (unit tests) they are English.
- Strings live in `i18n/messages/<area>.ts`, one file per area, every language in one typed object (only English
  and Czech shown in this example):

```ts
type DashboardMessages = { refresh: string; assets: (count: number) => string };

export const DASHBOARD_MESSAGES: Localized<DashboardMessages> = {
  en: {
    refresh: "Refresh positions",
    assets: (n) => plural("en", n, { one: `${n} asset`, other: `${n} assets` }),
  },
  cs: {
    refresh: "Obnovit pozice",
    assets: (n) =>
      plural("cs", n, {
        one: `${n} aktivum`,
        few: `${n} aktiva`,
        other: `${n} aktiv`,
      }),
  },
};
```

A missing string in any language is a type error. Interpolate with functions, never with string concatenation in
the component, because word order differs.

- `i18n/format.ts`: `plural` (by CLDR: Czech one / few / many / other, English, Spanish and German one / other, Hindi
  one / other with 0 as one, Vietnamese other only), `formatLongDate` ("14. října 2026", "14 de octubre de 2026",
  "14 अक्टूबर 2026", "14. Oktober 2026", "14 tháng 10, 2026"), `joinList` ("Signal, Telegram a e-mail", "Signal,
  Telegram y correo electrónico", "Signal, Telegram और ईमेल", "Signal, Telegram und E-Mail", "Signal, Telegram và
  email", no comma before the last word; Spanish "y" becomes "e" before an i sound and "o" becomes "u" before an o
  sound) and `formatDecimal` (a decimal comma in running text in Czech, German and Vietnamese; Spanish and Hindi keep
  the decimal point). `LOCALE_INFO[locale].numbers` is the Intl tag for numbers: the language's own, except Hindi,
  which uses `en-US` so amounts group in thousands like the app. Market wording: `csOnMarket`, `esMarket`, `hiMarket`,
  `deOnMarket`, `viMarket`.
- Metadata: pass `locale` and `alternates` (`routeAlternates(...)`, or only the published translations of a post) to
  `pageMetadata`. It writes the canonical, hreflang with `x-default` English, `og:locale` and the language's RSS link.
- Each alert channel has its own language, picked next to its recipient in the alert form; a new channel starts in
  the page's language (`notification_configs.email_locale`, `signal_locale`, `telegram_locale`). A channel
  without one is sent in `notification_configs.locale`, the page language the alert was last saved from. The alert
  text, the email subject and html and the test messages come from `i18n/messages/notifications.ts`; the cron and
  `POST /api/notifications/test` pick the language per channel.
- The Telegram bot's replies (`i18n/messages/telegram.ts`) follow the sender's Telegram app, not the site: Czech for
  Czech and Slovak (`cs`, `sk`), Spanish for any Spanish (`es`, `es-MX`, ...), Hindi, German and Vietnamese for those
  (`hi`, `de`, `de-AT`, `vi`), English otherwise.
- Fonts: Satoshi covers English, Czech, Spanish and German. It has no Devanagari, so the Hindi social cards add Noto
  Sans Devanagari (`app/fonts/og`, SIL Open Font License) as a fallback font and the Hindi pages fall back to the
  system's Devanagari font. It also lacks most Vietnamese letters (ơ, ư and the stacked tone marks), and a per-letter
  fallback would mix two typefaces inside one word, so the Vietnamese pages and cards use Plus Jakarta Sans (SIL Open
  Font License) for all text instead: `components/fonts/vietnamese.ts`, loaded only by `app/(vi)/layout.tsx`, and
  its OG files in `app/fonts/og`.
- The sign-in message the wallet signs carries a one-line statement in the page's language
  (`signInStatement` in `i18n/messages/alerts.ts`).

## Czech voice

- Formal address, lowercase: **vy, váš, vám**, never tykání. Buttons and menu items use the infinitive
  ("Uložit upozornění", "Obnovit pozice", "Připojit peněženku"); sentences use the vy imperative ("Připojte
  peněženku, se kterou si půjčujete").
- Sentence case, as in English. No em or en dashes anywhere (ranges with a plain hyphen: "1,5-2,0").
- Czech quotation marks in running text: „takto". Decimal comma in prose ("1,66"); data shown in the dashboard
  (amounts, health factor badges) keeps the app's number format.
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date
  and caveat of the English. Never add claims.
- Dates in prose: "14. října 2026". "As of October 2026" is "k říjnu 2026".

## Spanish voice

- One neutral Spanish for Spain and Latin America. No voseo and no vosotros; avoid words only one region uses
  ("ordenador", "móvil", "celular", "coger"). Prefer the word both understand: "billetera" for wallet, "tasa" for
  rate, "costo" for cost, "teléfono" for phone.
- Informal address, **tú, tu, te**, never usted. Buttons and menu items use the infinitive ("Guardar alerta",
  "Actualizar posiciones", "Conectar billetera"); sentences use the tú imperative ("Conecta la billetera con la que
  pides prestado").
- Sentence case, as in English. Opening marks always: "¿Qué es el factor de salud?", "¡Listo!". No em or en dashes
  anywhere, no raya for asides (ranges with a plain hyphen: "1.5-2.0").
- Numbers as the app shows them and as Latin America writes them: decimal point ("1.66"), comma for thousands
  ("12,000 USDC", "$2,400"), percentages without a space ("83%").
- Dates in prose: "14 de octubre de 2026", months in lower case. "As of October 2026" is "a octubre de 2026".
- Double quotation marks: "así".
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date and
  caveat of the English. Never add claims.

## Hindi voice

- Standard Hindi (मानक हिंदी) in Devanagari, the register of a careful explainer, not of a bank's terms: short
  sentences, everyday words, the technical term in Latin script where Indian crypto readers use it that way.
- Polite address, **आप, आपका, आपको**, never तुम or तू. Buttons and menu items are short imperatives in the आप form
  ("अलर्ट सहेजें", "पोज़िशन रीफ़्रेश करें", "वॉलेट कनेक्ट करें"); sentences use the same form ("उस वॉलेट को कनेक्ट
  करें जिससे आप उधार लेते हैं").
- Sentences end with the danda "।", questions with "?". No em or en dashes anywhere; a colon, a comma or "से" for
  ranges ("1.5 से 2.0" or "1.5-2.0" with a plain hyphen). Straight double quotation marks "…".
- Numbers exactly as the app shows them: Latin digits, decimal point ("1.66"), Western thousands grouping
  ("12,000 USDC", "$2,400"), never lakh or crore grouping or words ("12 लाख"), percentages without a space ("83%").
  "1.62 billion" is "1.62 अरब" (an arab is 10^9; never "बिलियन" alone when a reader may take it for 10^12).
- Dates in prose: "14 अक्टूबर 2026", months as Intl `hi-IN` writes them (जनवरी, फ़रवरी, मार्च, अप्रैल, मई, जून, जुलाई,
  अगस्त, सितंबर, अक्टूबर, नवंबर, दिसंबर). "As of October 2026" is "अक्टूबर 2026 तक".
- Technical terms in Devanagari transliteration with the English in brackets on first use, then the transliteration
  alone: "हेल्थ फ़ैक्टर (health factor)", "लिक्विडेशन (liquidation)", "कोलैटरल (collateral)". Code, contract and
  function names, error names and addresses stay in Latin script in backticks.
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date and
  caveat of the English. Never add claims.
- Never "मुफ़्त", "मुफ्त", "फ़्री", "फ्री" or "निःशुल्क" (the Hindi "free"; see the design system's voice rules):
  "भुगतान की ज़रूरत नहीं", "कोई शुल्क नहीं", "बिना भुगतान के".

## German voice

- One standard German for Germany, Austria and Switzerland. Avoid words only one country uses ("Jänner", "parkieren");
  write "ss" and "ß" the German way (Swiss readers understand both).
- Informal address, **du, dein, dir**, lower case, as German fintech apps write it; never "Sie". Buttons and menu
  items use the infinitive ("Alert speichern", "Positionen aktualisieren", "Wallet verbinden"); sentences use the du
  imperative ("Verbinde die Wallet, mit der du leihst").
- Sentence case: German capitalises nouns, nothing else in a heading ("Was ist ein sicherer Health Factor?"). No em
  or en dashes anywhere, although German typography likes them: a colon, a comma, a full stop or "bis" ("1,5 bis 2,0",
  or "1,5-2,0" with a plain hyphen).
- Numbers the German way: decimal comma ("1,66"), a dot for thousands ("12.000 USDC", "2.400 $"), a space before the
  percent sign ("83 %"). "Billion" in English is "Milliarde": "1,62 Mrd. USDC" or "1,62 Milliarden USDC"; never
  "Billion", which is 10^12 in German.
- Dates in prose: "14. Oktober 2026". "As of October 2026" is "Stand Oktober 2026".
- German quotation marks: „so“.
- English DeFi terms stay where German DeFi readers use them (Health Factor, Wallet, Loop, Stablecoin, E-Mode), with
  a German gloss on first use where it helps. Plain words where money is involved. Translate meaning, not word order;
  keep every fact, number, source, date and caveat of the English. Never add claims.
- Never "kostenlos", "gratis", "umsonst", "kostenfrei" or "gebührenfrei" (the German "free"; see the design system's
  voice rules): "keine Zahlung nötig", "kostet nichts", "ohne Gebühr".

## Vietnamese voice

- Standard Vietnamese as written in Vietnam today, in the register of a careful explainer: short sentences, plain
  words, no Sino-Vietnamese where an everyday word exists. Old-style tone placement, the same everywhere ("hòa",
  "khỏe", "thủy", never "hoà", "khoẻ").
- Address the reader as **bạn**, never "quý khách", "anh/chị" or "mày". Buttons and menu items are short verbs
  ("Lưu cảnh báo", "Làm mới vị thế", "Kết nối ví"); sentences speak to bạn directly ("Kết nối ví mà bạn dùng để vay").
- Sentence case: only the first word and names are capitalised. No em or en dashes anywhere: a colon, a comma, a full
  stop or "đến" ("1,5 đến 2,0", or "1,5-2,0" with a plain hyphen). Straight double quotation marks "như thế này".
- Numbers the Vietnamese way: decimal comma ("1,66"), a dot for thousands ("12.000 USDC", "2.400 $"), percent without
  a space ("83%"). "Billion" is "tỷ" ("1,62 tỷ USDC"), "million" is "triệu".
- Dates in prose: "ngày 14 tháng 10 năm 2026". "As of October 2026" is "tính đến tháng 10 năm 2026".
- DeFi terms: the Vietnamese term with the English in brackets on first use, then the Vietnamese term alone ("hệ số
  sức khỏe (health factor)"). Product, token and network names, code, contract and error names stay as written.
- Plain words where money is involved. Translate meaning, not word order; keep every fact, number, source, date and
  caveat of the English. Never add claims.
- Never "miễn phí" (the Vietnamese "free"; see the design system's voice rules): "không cần thanh toán", "không mất
  phí".
